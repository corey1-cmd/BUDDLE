# RSS → 화제(Topic) 데이터 변환 알고리즘

버들의 "지금 화제"는 **AI(LLM) 호출 0회**로 만들어진다. RSS 헤드라인이 사용자에게
보이는 화제 카드가 되기까지 데이터가 통과하는 단계와, 각 단계의 알고리즘·근거를
설명한다.

> 코드 위치: `src/buddle/ai/news/fetcher.py`(1–2단계) ·
> `src/buddle/services/news_service.py`(3–4·8단계) ·
> `src/buddle/ai/news/topics.py`(5–7단계) ·
> `src/buddle/api/v1/news.py`(9단계)

```
① RSS 수집 → ② XML 파싱 → ③ 중복 제거(DB UNIQUE) → ④ 알고리즘 분석(분류·발췌)
 → ⑤ 키워드 추출 → ⑥ 화제 클러스터링 → ⑦ 다이제스트 합성 → ⑧ 캐시 → ⑨ 필터 API
```

---

## ① 수집 (fetch)

- 관리자가 등록한 소스 레지스트리(Redis)를 읽어 소스별로 가져온다.
  종류: **RSS/Atom**(BBC·Guardian·대한민국 정책브리핑 등), **Hacker News** API,
  **dev.to** API.
- 인증 없는 공개 피드만 사용하고, 요청엔 식별 User-Agent를 붙인다.
- 소스 등록 시 URL이 사설 IP/localhost로 풀리면 거부한다(SSRF 가드).
- **본문은 수집하지 않는다.** 제목·링크·매체명·피드가 제공한 요약 스니펫까지만 —
  권리 엔진의 default-deny 정책과 일치.

## ② 파싱 (parse)

정규식 기반 경량 XML 파서(외부 라이브러리 無)가 `<item>`/`<entry>` 블록에서 뽑는 것:

| 필드 | 처리 |
|---|---|
| `title` | 태그 제거 → **HTML 엔티티 해제**(`&apos;`→`'`) → 공백 정리 |
| `link` | `<link>` 본문 또는 `href` 속성 |
| `description`/`summary`/`content` | 태그 제거 → 엔티티 해제 → 2,000자 캡 |
| `pubDate`/`published`/`updated` | RFC-822·ISO-8601 파싱 → unix 초. 실패 시 수집 시각 |

`pubDate`는 ⑥의 최근성 가중치 입력, 요약은 ⑤ 키워드와 발췌 요약의 입력이다.

## ③ 중복 제거 (dedup) — 2중 방어

1. **Redis seen-set** (값싼 선필터): URL 해시가 최근에 본 것이면 건너뜀. TTL 기반.
2. **DB가 최종 보증**: `news_items.guid UNIQUE` + `INSERT … ON CONFLICT DO NOTHING`.
   guid는 RSS GUID 또는 URL 해시 — 재수집·Redis 초기화·다중 인스턴스 어떤 경우에도
   같은 기사는 한 번만 저장된다.

Redis만 쓰던 시절 재시작으로 기록이 소실된 실측 사례 2회가 DB 승격의 근거다.

## ④ 기사 단위 알고리즘 분석 (LLM 대체)

새 기사마다 순수 함수 3개가 돌며, 결과는 `news_items` 컬럼으로 저장된다:

**(a) 주제 분류 `classify_category`** — 사전 기반 투표.
6개 버킷(환경·교육·경제·정치·기술·사회)마다 한/영 어휘 사전을 두고, 기사
키워드와의 교집합 크기가 가장 큰 버킷을 채택한다. 무승부·무일치는 "사회".

**(b) 범위/지역 분류 `classify_region`** — 행정구역 렉시콘, **입자 우선**.
```
구(자치구 화이트리스트) 발견 → 동네     예) "마포구 가로등 고장" → (동네, 마포구)
시(주요 시 ~70개) 발견     → 시       예) "성남시 버스 노선 개편" → (시, 성남)
도/광역 발견               → 도
지역 단서 없음 + 국내 소스/한국어 → 전국  예) "AI 규제 법안 통과" → (전국, ·)
그 외                      → 해외
```
좁은 단서일수록 위치가 중요한 이슈라는 관찰을 그대로 규칙화한 것. 접미사 추론
대신 화이트리스트만 써서 "도시/역시" 같은 오탐을 차단한다.
**위치 자동 매칭은 하지 않는다** — 분류만 저장하고, 좁히는 것은 사용자의 필터다.

**(c) 발췌 요약 `extractive_gist`** — 생성 없음.
요약 스니펫을 문장 분리해 첫 문장(짧으면 둘째까지)을 180자 캡으로 자른다.
원문에 있던 문장만 나가므로 환각이 구조적으로 불가능하다.

## ⑤ 키워드 추출 `extract_keywords`

한글 2자+/영문 3자+ 토큰화 후 3단 필터:

1. **조사 접미 제거**: "반도체의"→"반도체", "수출이"→"수출" (어근 2자 이상 보존)
2. **스톱워드**: 일반 불용어 + **저널리즘 상투어**("개편·발표·확정·논란·급증"…).
   상투어가 화제 이름이 되면 무관한 기사를 한 클러스터로 묶는다
   (실측: '개편'이 버스 노선 개편과 보조금 개편안을 병합했다)
3. **동사 활용형 제외**: "조정되고·늘어난다"처럼 활용 어미로 끝나는 토큰은
   개체가 아니라 서술어이므로 제외

## ⑥ 화제 클러스터링 `build_topics` — 핵심 단계

최근 **72시간** 창의 기사(최대 500건)를 키워드 공유로 묶는다.

**점수식** — 키워드 k의 점수:

```
score(k) = Σ_기사 [ recency × (1 + ln(1+engagement)/4) ] × diversity

recency   = exp( −경과시간h / 24h × ln2 )     # 24시간 반감기
diversity = 1 + 0.3 × (매체 수 − 1)           # 다양성 부스트
```

- **최근성 반감기 24h**: 하루 지난 기사는 가중치 절반 — 오늘의 화제가 위로.
- **참여도 로그 감쇠**: HN 점수 같은 신호는 log로 눌러 바이럴 1건의 지배를 방지.
- **소스 다양성**: 같은 매체 3건보다 세 매체 1건씩이 더 높은 점수 — "여러 매체가
  동시에 다루는 것"이 화제의 정의에 가깝다.

**병합**: 두 키워드의 기사 집합이 **60% 이상 겹치면** 한 화제로 흡수(높은 점수가
이름, 나머지는 별칭). "반도체/semiconductor" 류 중복 카드를 제거한다.

**최소 지지 min_count=2**: 기사 1건짜리 키워드는 화제가 아니라 잡음 — 버린다.

화제의 주제/범위/지역은 클러스터 소속 기사들의 **합산 텍스트**로 ④와 같은
분류기를 다시 돌려 정한다(다수 기사의 합의가 개별 기사 오분류를 상쇄).

## ⑦ 다이제스트 합성 `compose_digest`

상위 화제를 고정 한국어 템플릿에 끼워 한 단락을 만든다:
"오늘의 흐름: '규제', '전기차' 관련 소식이 이어지고 있어요(경제, 정치). …"
생성이 아니라 조립이므로 집계 수치와 항상 일치한다.

## ⑧ 캐시

결과는 Redis `buddle:news:topics`(TTL 25h)에 저장. 읽기는 캐시 우선, 비어 있으면
DB에서 재계산 후 재캐시. 파이프라인은 스케줄러(기본 1시간) 또는 관리자 수동
실행(`POST /v1/admin/news/tick`)으로 돈다.

## ⑨ 사용자 제공 `GET /v1/news/topics`

- 필터: `scope`(동네|시|도|전국|해외) · `category`(환경|교육|경제|정치|기술|사회)
  정확 일치, `region` 부분 일치(선택).
- 응답은 화이트리스트 필드만 명시 구성 — 이름·건수·매체·분류·헤드라인
  (제목/링크/매체명). 내부 점수·키워드는 구조적으로 노출 불가.
- 홈의 "지금 화제" 스트립과 관심주제의 필터 섹션이 이 API 하나를 소비한다.

## 왜 LLM이 아니라 알고리즘인가

| | 기사당 LLM 호출(구) | 알고리즘(현재) |
|---|---|---|
| 외부 API 호출 | 기사당 1회 + 다이제스트 1회 | **0회** |
| 장애 모드 | 쿼터 소진 → 429 연쇄(실측) | 없음 |
| 비용 | 수집량에 비례 | 0 |
| 재현성 | 비결정적 | 같은 입력 → 같은 출력 |
| 환각 | 가능 | 불가능(발췌·집계만) |

화제 제시는 "긴 요약 생성"이 아니라 "단편 데이터의 군집·랭킹" 문제라서
결정론적 알고리즘이 구조적으로 적합하다. 기존 LLM 분석 경로는 삭제하지 않고
`NEWS_AI_ANALYSIS_ENABLED=true`로만 켜지는 opt-in으로 남겨두었다.
