# 주장·인물 AI 대화 (RAG) — 설계 (ARGUMENT_AI.md)

작성: 2026-06-12 · 마이그레이션 0021 · 상태: 설계 → 구현

## 0. 무엇을, 왜

사업계획서 ④ 기능: 댓글·DM을 하기엔 애매한 간극을 메운다. 글의 **주장**이나
글쓴이의 **사고방식**을 학습한 AI와 대화하고, 그 대화에서 나온 근거·맥락을 원글에
함께 저장한다. 투자제안서가 "핵심 통찰"로 꼽은 바로 그 기능.

## 1. 핵심 결정 — 파인튜닝이 아니라 RAG

"그 사람의 사고방식을 학습한 AI"를 **검색 조건화(RAG; Lewis et al. 2020,
NeurIPS)**로 구현한다. 파인튜닝이 아니다. 이유 셋:

1. **비용 0** — 모델을 새로 학습하지 않는다. 공개 글·논증 유닛을 검색해 프롬프트에
   조건으로 넣을 뿐.
2. **즉시 반영** — 새 글이 올라오면 다음 대화부터 바로 컨텍스트에 들어간다.
3. **삭제권과 구조적 정합** — 사용자가 글을 지우면 검색 코퍼스에서 사라져 **즉시
   잊힌다**. 파인튜닝은 학습된 가중치에서 특정인을 지우는 것이 사실상 불가능 →
   데이터 주권·개인정보보호법과 충돌. RAG는 그 충돌이 원천적으로 없다.

## 2. 대화 모드 2종

| 모드 | 컨텍스트(검색 코퍼스) | 의미 |
|---|---|---|
| 주장 AI (claim) | 해당 post 본문 + 그 글의 argument_units + 같은 화제 인접 유닛 top-k(코사인) | "이 주장과 대화" — 글 하나의 논지를 깊이 파봄 |
| 인물 AI (author) | 그 작성자의 **공개** 글·논증 유닛 top-k + 공개 동의된 프로파일 요약 | "이 사람의 생각과 대화" — 글쓴이의 사고 결을 재현 |

둘 다 **공개 글 한정**. 비공개·억제(suppressed) 글은 코퍼스에서 제외.

## 3. 3중 안전장치 (윤리 리스크 선제 차단)

인물 재현은 윤리 리스크가 크다. 그래서 시스템 프롬프트에 3중으로:

1. **명시 라벨 강제** — "이 대화는 글쓴이의 공개 글로 구성한 AI 재현이며 본인이
   아닙니다." UI 상단에도 고정 노출.
2. **컨텍스트 밖 사실 단정 금지** — 검색된 근거에 없는 내용을 그 사람의 입장인 양
   단정하지 말 것. 모르면 모른다고.
3. **백혈구 게이트** — 기존 leukocyte 안전 검열을 응답 전에 통과.

추가로 작성자 **`argument_ai_opt_out`** 필드 — 거부한 사람의 글·인물 AI는 **404**.
AI 기본법 투명성 의무와 정합.

## 4. post_context_notes — 대화 산출의 적재

대화에서 나온 유용한 뒷받침·부가정보를 원글에 저장(사업계획서 ④의 "포스트에
근거·맥락 함께 저장" 문구 그대로). 피드 상세의 "이 글의 부가 맥락" 섹션으로 노출.

`post_context_notes`: `(id, post_id FK, kind ENUM[context,evidence,clarification],
content, source_session_id, created_at)`. 적재는 명시적(사용자가 "이 답변을
맥락으로 저장")이거나 대화 종료 시 요약 — 무분별 적재 방지.

## 5. 데이터 흐름

```
"이 주장과 대화" / "이 사람과 대화" 클릭
  │
  ├─ WS /v1/ws/argument/{post_id}?mode=claim|author  (인증·origin·레이트리밋 공유)
  │     │
  │     ├─ opt-out 확인 → 거부 시 404 (작성자가 인물 AI 비활성화)
  │     ├─ 공개 글 확인 → 비공개면 거부
  │     │
  │     └─ 매 사용자 턴:
  │           ├─ retrieve(mode, post, query) → 근거 top-k (argument_units 코사인)
  │           ├─ build_prompt(라벨 + 근거 + 안전지침)
  │           ├─ leukocyte 게이트
  │           └─ 페르소나 백엔드로 생성 (기존 vllm_endpoint/stub)
  │
  └─ "맥락으로 저장" → post_context_notes 적재 → 피드 상세에 노출
```

## 6. 구현 순서
1. 순수층 `ai/argument/retrieval.py` — 검색 결과 → 프롬프트 컨텍스트 구성(결정적).
2. DB: `post_context_notes`(0021) + personas.argument_ai_opt_out 컬럼.
3. 서비스 `argument_chat_service` — 검색·프롬프트·노트 적재.
4. WS 핸들러 `/v1/ws/argument/{post_id}` — 공유 인프라 재사용.
5. 노트 읽기 API + 피드 상세 노출 + feed/dashboard의 "대화" 버튼 연결.

각 단계 게이트: pytest 전량 / ruff / mypy --strict / 스텁 결정성.
